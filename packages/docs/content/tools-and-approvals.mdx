Tools let a bot do things: read a web page, search, or work in your apps through
a [connector](/docs/connectors). You decide which tools each bot gets, and
which ones need a member to say yes.

## Built-in tools

Every bot comes with these while the workspace allows [web search](/docs/web-search),
unless someone turns them off for it.

<BuiltInTools />

- **Read web pages** reads public pages only. It can't sign in to anything, and
  it can't reach your private network unless the server allows it with
  [`ALLOW_PRIVATE_WEB_FETCH_NETWORK`](/docs/configuration#network).
- **Search the web** uses the workspace's [search provider](/docs/web-search#choose-a-provider).

To switch one off for a bot, open the bot's settings, go to **Tools**, and use
**Turn off**.

Bots can also [ask each other for help](/docs/chats#bots-asking-bots).
That's always on.

## Tools from connectors

A connector's tools belong to its project, a bot's own to its default
project. Each tool has its own access setting. These settings apply when
the member's role and the work the bot is doing allow the call:

| Tool access | What happens |
| --- | --- |
| Off | Every call is refused, and the bot is told the tool is off |
| Ask | Every call waits for a member |
| Allow | Every call runs straight away |

A [personal bot](/docs/bots#public-private-and-personal) asks its creator before every
call that changes something, even on **Allow**, because it can reach everything
they can.

Until someone chooses, a tool is on **Allow** when the connector says it only
reads, on **Off** when it says the tool deletes or overwrites, and on **Ask**
otherwise. A choice stays, even while the connector stops listing the tool. Turning a tool off
also stops a call someone already allowed but that hasn't run yet.

To change them, open **Connectors** beside the bot's chats. Each row's
menu sets every tool of that connector at once, and says **Custom** when they
differ. Open a connector to see its tools, the ones that read apart from the
ones that make changes: each group's menu sets all of its tools, and each tool
can be set on its own.

## Try it

Set the tool's access and pick what the bot wants to do. A member's role and the kind of work the bot is doing can also affect
whether a call runs or needs approval. For example, Sugabots refuses a call
that would write to a connector for a viewer in a project, even on **Allow**.

## Who can answer

If you can answer a waiting call, you'll see **Allow** and **Deny**. Allow
applies to that call and the details shown. A request shows the page's
address for a browser action and, to whoever can answer it, the address a
connector sends to; its expanded view shows the exact input. If the input is
too large to show in full, Sugabots refuses the call. Allowing a browser
action lets the bot act anywhere on that page, which may change before you
decide. For GitHub, a request also shows what the bot didn't name but the
call will use, such as the repository's default branch for a new pull
request, or the commit a review is for. A request to start a chat shows which
bot receives the brief and which project the chat starts in, or whether it
starts in the bot's own chats. A request to create or change a routine shows
the time zone it will run in.

If something the request depends on changed after the bot asked, choosing
**Allow** closes the request and gives the reason. Here's what
can change while a request waits.

- A connector or its tool settings changed, or the GitHub call would go to a different destination.
- A connector or one of its tools was switched off. This includes a bot's own
  connector that needs to be turned on again for the project after an address change.
- The brief's recipient or destination changed.
- No computer provider is enabled.
- The bot can no longer use the computer.
- The computer the bot would use changed.
- The host is now blocked.
- The automation's routine changed.
- The workspace time zone changed while the bot was asking to create or change a routine.
- A tool was switched off.
- The automation was removed.

The closed request says what to do next. If the request itself changed, such
as the connector or the brief's destination, ask the bot to try again. If a
setting now stops the call, someone has to change it first. The workspace's
owner or an admin can turn a connector back on for a project, including a
bot's own connector used there. In the bot's own chats, whoever manages
the bot can turn its connector back on. Whoever manages the connector can
change a tool's access in the connector's settings. Whoever manages the bot
can turn a built-in tool or computer use back on. The workspace's owner or an
admin can enable a computer provider or unblock a host. A removed automation
can't be edited.

A request also stops waiting without anyone answering when:

- nobody answers within 7 days;
- a new message reaches the bot, or someone stops it;
- the automation run it belongs to ends;
- the bot's reply fails;
- the chat is no longer available.

The request then says why, and what you can do next.

The first rule that applies decides who can answer:

1. **Requests to change a computer.** The workspace's owner and admins
   answer for projects members made. For a public or private bot's own
   computer, its creator can also answer if they can talk to the bot and have
   a role other than viewer. Only the creator answers for their own personal
   bot's computer, whatever their role. If they cannot open the chat, they
   still see the details they need to decide, such as the requested host.
   Approving a request to add an allowed host adds it for the project,
   even if the computer is replaced.
2. **Other calls by a personal bot.** Only its creator can answer, including
   for calls it makes during an automation run.
3. **Other calls made by an automation.** The workspace's owner and admins
   can answer if they can read the run's chat. The creator of the bot doing
   the run can also answer if they can manage that bot and read the run's chat.
4. **Other calls in a chat.** Only the member whose message the bot is
   answering can decide, including when the bot has asked another bot for help.

Sugabots checks who can answer when they submit their decision. When the
call starts, the current tool, connector and computer settings still apply.
