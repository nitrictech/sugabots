---
title: Routines
description: Jobs a bot does on a schedule, or whenever something calls it.
---

A routine is a job for one bot: "every weekday at 8, sort the inbox" or "when the
shop gets an order, draft a thank-you". The bot does it without being asked, and
posts what it did into its chat.

Admins create and manage routines in **Settings → Routines**, and switch them on
or off from that list. Members and viewers can see them.

## Make a routine

Choose **New routine**, then pick:

- **Bot**: who does the job.
- **Instructions**: what to do each time, written like you'd ask in the chat.
- **Triggers**: what starts it. Choose **Add trigger** for each one: a
  **Schedule**, a **Webhook**, or **GitHub** when the bot's pod is connected to
  GitHub. A routine can have several, such as two schedules and a webhook, and
  one with none runs only when someone chooses **Run now**.
- **Post result to chat**: whether the bot's answer goes in its chat for people
  to read, or stays inside the run.

## Where the result goes

With **Post result to chat** on, the bot's last reply of the run is posted in its
chat, where anyone can answer it and carry on the conversation. Use it for
anything people should read: a morning check-in, the week's sales, a reminder. The bot is
told its last reply goes there, so it writes that reply for you.

With it off, the result stays inside the run, for work handled out of sight,
such as drafting a thank-you for each new order. You can still open the run to see it.

It starts on for a routine whose first trigger is a schedule, and off otherwise.

A schedule uses the timezone of whoever created the routine, or the workspace's
when a bot set it up. If Sugabots was down when a run was due, it does one
catch-up run rather than all the missed ones, and a routine never runs twice at
the same time.

## Ask the bot

Admins can also ask a bot in its chat: "check in with me every morning at 9" or
"move the inbox sweep to 10". It sets up, changes or pauses its own schedules, in
the workspace's timezone, and links to the routine in its reply. Once a routine
has more than one trigger, its schedule is changed in settings. Anyone in the
pod can ask a bot what routines it has. Webhooks, and deleting a routine, stay
in **Settings → Routines**.

Turn **Manage its routines** off in a bot's settings to stop it.

## When something calls it

A **Webhook** trigger runs its routine whenever its address is called, so other apps can set
a bot to work. Each webhook has an address and a secret of its own; open it from the
routine's **Triggers** to see them. The secret stays hidden until **Show**.

<Careful title="Changing the secret">

The old secret stops working as soon as a new one is saved, so update the app
that calls the address straight away.

</Careful>

Call the address with a JSON body and a `Content-Type` of `application/json`, up to
64 KiB. The bot gets the body along with its instructions, marked as data from outside
so it isn't taken as orders. The caller proves it holds the secret the way the
webhook's **Source** and **Auth** say:

- **GitHub**, **Stripe**, **Slack** or **Linear**: paste the signing secret the
  sender made, and add the address in the sender, which signs each call itself.
  Slack's address check is answered for you.
- **Generic**, for any other sender, with one **Auth**:
  - **HMAC**: the sender signs the raw body with the secret and sends the digest in
    the **Header** you name. Pick SHA-1, SHA-256 or SHA-512, and hex or base64. A
    leading `sha256=` is fine.
  - **Bearer**: `Authorization: Bearer <secret>`.
  - **API key**: the secret in the **Header** you name.
  - **Basic**: HTTP Basic auth with the **Username** you set and the secret as the
    password.

The secret goes in a header, never in the address. A secret you make up needs at
least 16 characters. A webhook with no secret is run by anyone who has its address.

For example, with **Bearer** auth:

```sh
curl -X POST "https://sugabots.example.com/api/hooks/triggers/<trigger id>" \
  -H "Authorization: Bearer <secret>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042" \
  -d '{"order": 1042, "customer": "Sam"}'
```

A sender that signs, such as Sentry, needs no custom headers. Choose **Generic**,
**HMAC**, SHA-256 and hex, set the **Header** to `Sentry-Hook-Signature`, and
paste the integration's client secret as the secret.

A call is answered with `202` and an `executionId` as soon as the run is queued,
without waiting for the bot. Otherwise:

- `401` if the secret or signature is wrong, or the webhook is off or gone.
- `400` if the body isn't JSON or the delivery id is over 200 characters.
- `413` if the body is over 64 KiB.

A delivery id makes a retry land on the run the first call started, which the
reply marks `"duplicate": true`. Sugabots reads it from `Idempotency-Key`,
`Linear-Delivery`, `X-GitHub-Delivery`, `X-Shopify-Webhook-Id`, `Svix-Id` or
`Webhook-Id`, else a Slack `event_id` or a Stripe event's `id` in the body. With
none, every call starts a run. The same id sent with a different body is refused
with `409`.

## Runs

Each run shows in the bot's chat as a line like "Morning inbox sweep ran", and
opens into a thread with everything the bot did. A result posted to the chat
links back to its run, under the message. A run that fails or is stopped posts
nothing; its line says what happened. If a run needs an
[approval](/docs/tools-and-approvals), only an admin can answer it.
