title: Routines
description: Jobs a bot does on a schedule, or whenever something calls it.

A routine is a job for one bot: "every weekday at 9, start the standup" or "when
Sentry reports an issue, look into it". The bot does it without being asked, in
its chat.

Admins create and manage routines in **Settings → Routines**, and switch them on
or off from that list. Members and viewers can see them.

## Make a routine

Choose **New routine**, then pick:

- **Bot**: who does the job.
- **Instructions**: what to do each time, written like you'd ask in the chat.
- **When**: a **Schedule** or a **Webhook**.
- **Post result to chat**: whether the bot's answer goes in its chat for people
  to read, or stays inside the run.

## Where the result goes

With **Post result to chat** on, the bot's last reply of the run is posted in its
chat, where anyone can answer it and carry on the conversation. Use it for
anything people should read: a morning standup, a check-in, a report. The bot is
told its last reply goes there, so it writes that reply for you.

With it off, the result stays inside the run, for work handled out of sight,
such as fixing an issue a webhook reports. You can still open the run to see it.

New schedules start with it on, and new webhooks with it off.

A schedule uses the timezone of whoever created the routine. If Sugabots was down when a run was due, it does one
catch-up run rather than all the missed ones, and a routine never runs twice at
the same time.

## When something calls it

A **Webhook** routine runs whenever its address is called, so other apps can set
a bot to work. When you save it, Sugabots shows the address and a secret.

<Careful title="Copy the secret now">

It isn't shown again. **Reset** makes a new one, and the old one stops working
straight away.

</Careful>

Call the address with a JSON body and the secret as a bearer token. The bot gets the
body along with its instructions, marked as data from outside so it isn't taken
as orders.

```sh
curl -X POST "https://sugabots.example.com/api/hooks/routines/<routine id>" \
  -H "Authorization: Bearer <secret>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042" \
  -d '{"order": 1042, "customer": "Sam"}'
```

`Idempotency-Key` is optional. Send the same key twice and the second call is
recognised as a repeat.

## Runs

Each run shows in the bot's chat as a line like "Morning standup ran", and
opens into a thread with everything the bot did. A result posted to the chat
links back to its run, under the message. A run that fails or is stopped posts
nothing; its line says what happened. If a run needs an
[approval](/docs/tools-and-approvals), only an admin can answer it.
